## Implementation

| Component | Responsibility |
| --- | --- |
| `DependencyGraph` | Convert Phase 2 AST references into directed internal file dependencies, external/unresolved references and reverse-dependency groups |
| `ManifestWriter` | Serialize YAML manifests, preserve identical files, safely replace MATMA-owned output and remove stale MATMA-owned manifests |
| `IndexCommand` | Run full validation, graph construction and manifest regeneration through `php artisan matma:index` |
| `DiscoveryVisitor` (extended) | Record dynamic class instantiation/static/instanceof expressions without inventing a named dependency |

The indexer uses `nikic/php-parser` through the Phase 2 `ProjectInspector` and serializes with Symfony YAML. It does not change application source, rename Laravel classes, generate tests or execute tests.

## Graph semantics

- Each PHP source file containing at least one class-like declaration becomes a **file-owned graph node**. A normal Laravel class file provides its fully qualified `class_name`; an anonymous-only file uses a `file:<source_file>` symbol ID and a null class name.
- Named class symbols resolve case-insensitively (PHP semantics), while source paths retain their exact spelling and case. The Phase 2 structural validation must succeed before writing any index.
- Edges point from the referencing file **to** files containing actually referenced internal symbols. Unused imports do not create edges. Duplicate references to the same file produce one edge. Self-references stay local and do not form cross-file edges.
- Trait and enum files can be dependency nodes and propagate reverse impact but do not become independent mirrored *test targets*. Their unit, interaction and mock pointers are null.
- References not declared inside the indexed source root are explicitly included under `external_dependencies` with `resolution: external_or_unresolved` and null `source_file`. This distinguishes absent internal resolution without claiming that a package is installed.
- Dynamic new/instanceof/static-class expressions are recorded separately under `dynamic_references` with their AST line numbers. They are not guessed into named edges.
- Helper-only PHP files contribute to the project fingerprint but do not receive class manifests.

### Reverse-dependency levels

Reverse edges are computed once, during indexing. Breadth-first traversal gives each dependent its **shortest-path** distance from the changed source. Level N includes exactly the nodes at graph distance N; the later `impact --level N` command will interpret the requested N as an **inclusive radius**. Cycles are deduplicated and the origin is never rediscovered. Nodes and lists are consistently sorted.

The fixtures include a chain `Base ← Left/Right ← Top ← Leaf`, an isolated class, the two-node cycle `CycleA ↔ CycleB`, missing external symbols, trait/enum consumers and an anonymous-class file. Tests verify the shortest-path groups.

## Manifest schema and placement

Production source `app/Services/DocumentParser.php` maps to `tests/mirror/Services/DocumentParser.auto.yaml` beneath the configured tests root, without changing Laravel's PSR-4 naming.

~~~yaml
# AUTO-GENERATED BY MATMA AST INDEXER TOOL - DO NOT EDIT MANUALLY
schema_version: 1
index_fingerprint: '<sha256 of the deterministic source-file inventory>'
class_name: 'App\Services\DocumentParser'
symbol_id: 'App\Services\DocumentParser'
kind: class
source_file: 'app/Services/DocumentParser.php'
mirrors:
  unit_test: 'tests/unit/mirror/Services/DocumentParserTest.php'
  interaction_test: 'tests/interaction/mirror/Services/DocumentParserInteractionTest.php'
  mock_file: 'tests/mocks/mirror/Services/MockDocumentParser.php'
  mock_class: MockDocumentParser
  manifest: 'tests/mirror/Services/DocumentParser.auto.yaml'
dependencies:
  - class_name: 'App\Services\Formatter'
    source_file: 'app/Services/Formatter.php'
    kind: class
    mock_file: 'tests/mocks/mirror/Services/MockFormatter.php'
    mock_class: MockFormatter
external_dependencies: []
dynamic_references: []
dependents:
  level_1:
    - class_name: 'App\Http\Controllers\DocumentController'
      source_file: 'app/Http/Controllers/DocumentController.php'
      unit_test: 'tests/unit/mirror/Http/Controllers/DocumentControllerTest.php'
      interaction_test: 'tests/interaction/mirror/Http/Controllers/DocumentControllerInteractionTest.php'
~~~

This is an **illustrative schema**, not a generated example from an actual application. Generated manifests contain the actual keys and data for the indexed source.

**Generated YAML is deliberately not committed to Git.** The project's `.gitignore` excludes `/tests/mirror/**/*.auto.yaml`. The `schema_version` describes the *format*, not a version-controlled history. The `index_fingerprint` is computed from sorted source paths and their SHA-256 content hashes, including helper-only PHP files.

## Artisan interface

~~~bash
php artisan matma:index --source-root=app --tests-root=tests --format=json
php artisan matma:index --target='App\Services\DocumentParser' --format=yaml
php artisan matma:index --source-root=app --check
~~~

- Every invocation regenerates the **entire** graph to keep all reverse edges coherent. `--target` selects the named source in the command's result; it never reduces the work to a potentially inconsistent local update.
- `--check` preserves strict validation behavior; the index command refuses to write if any structural or parse errors exist even without `--check`.
- Exit `0`: success (`status: indexed`); `1`: invalid source/target, parse/structural violations, unsafe output, or manifest ownership/write error; `64`: invalid option values.
- `--scaffold` intentionally returns exit `2` (`not_implemented`) before writing any manifests, because creating failing tests and mocks belongs to Phase 4. Calling `matma:scaffold` remains deferred.
- `--format=text|json|yaml` controls CLI diagnostics only. The on-disk index always uses YAML.
- JSON/YAML output includes graph `summary` (source files, indexed files, internal edges, external and dynamic reference counts), `index_fingerprint`, optional `target`, and `manifests` paths grouped as `written`, `unchanged` and `removed`.

## Safe regeneration policy

1. Parse and validate **all** configured PHP source files before writing; if any fail, generate nothing.
2. Build all manifests and preflight output destinations before mutating files. Refuse to overwrite pre-existing `.auto.yaml` files that do not carry MATMA's explicit ownership header.
3. Write changed generated files via a temporary sibling file and rename it into place; leave byte-identical manifests unchanged.
4. After a successful rebuild, prune only stale `.auto.yaml` files with the exact MATMA ownership header. Never remove hand-written files or rewrite production PHP. Symlinks are not followed or overwritten.
5. A rebuild with an unknown `--target` or premature `--scaffold` request fails without writing.

Phase 3 does **not** provide a transactional multi-file filesystem commit or the Phase 5 stale-index *reader*. The generated fingerprint supports later freshness checks.

## Tests and CI

The unit tier was authored manually at `tests/unit/mirror/Indexing/` with real AST fixtures and real temporary filesystems, not fabricated parser output. Tests cover chains, diamonds, shortest-path levels, cycles, isolated nodes, external/unresolved and dynamic references, anonymous files, trait/enum dependencies, stable fingerprinting, byte-identical regeneration, ownership conflicts, stale cleanup, and unsafe paths.

Integration tests under `tests/interaction/mirror/Console/Commands/` exercise the real Artisan indexer with temporary YAML output, including target lookup, full rebuilds, validation errors, and `--scaffold` refusal. The Laravel 11 consumer smoke test installs the package and generates a real YAML manifest using `php artisan test`. The existing shared command double stays centralized in `tests/mocks/mirror/Console/`; no additional mocks are needed for deterministic filesystem/AST tests.

CI run [42291922018](https://github.com/rzepeda/matma-php/actions/runs/42291922018) passed all six jobs (five PHP/Laravel package combinations, plus native Laravel consumer). The checked package run completed **71 tests, 260 assertions**; the consumer completed **3 tests, 14 assertions**.

## Next phases

- **Phase 4:** Non-destructive `matma:scaffold` implementation; generated unit/interaction test stubs must **fail explicitly** until authored, and centralized mocks must respect unmockable dependencies.
- **Phase 5:** `matma:impact` reads exactly the persisted YAML index without re-parsing the source AST, checks freshness using the index fingerprint, and resolves an inclusive verification radius.
- Business and regression test tiers remain separately registered rather than inferred from mirrored class names.
